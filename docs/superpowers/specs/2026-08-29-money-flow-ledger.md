# 자금 원장 시각화 (kq-ledger) — 설계

*2026-08-29 · 브랜치 `feat/sector-flow` · 프로토타입 `src/kr_quant/tui/ledger_view.py`·`ledger_app.py`*

## 0. 한 줄

"돈이 어디서 어디로 갔나"를 **관측된 만큼만** 그린다. 관측된 것은 **(날짜, 시장, 섹터, 주체)의
순매수 금액**이고, 관측되지 않은 것은 **그 돈이 어느 섹터에서 왔는지**다. 이 문서의 절반은
그리지 않기로 한 것과 그 이유다.

---

## 1. 데이터가 지지하는 것 / 지지하지 않는 것

원천: `~/Documents/kr-quant-reports/latest/payload.json` (`scripts/sector_flow.py` 산출).
260 거래일(2025-08-05 ~ 2026-08-28), 2시장 × 27섹터 × 4주체.

### 1.1 관측되는 것 — 네 개의 실측 축

| 축 | 관측 여부 | 근거 |
|---|---|---|
| (날짜, 시장, 섹터, 주체) 순매수 금액 | **관측** | 페이로드 `flows[m][s][actor][i]` |
| 주체별 **주변합**(marginal) | **관측** | 위의 합 |
| 섹터별 4주체 합 ≈ 0 | **관측**(회계 항등식) | §3 실측 |
| 어느 주체가 **어느 주체에게** 넘겼나 | **미관측** | §2.2 — 주변합은 쌍별 흐름을 결정하지 않는다 |
| 어느 섹터에서 **어느 섹터로** 갔나 | **미관측** | §2.1 — 돈에 꼬리표가 없다 |

### 1.2 용어 교정 — "유입"이 아니다

`순매수`는 **소유권 이전**이지 시장으로의 **자금 유입**이 아니다. 모든 체결에는 같은 크기의
매수와 매도가 있다. 화면에서 "유입/유출"이라는 말을 쓰지 않고 **넘어간 쪽 / 넘긴 쪽**으로
적는다. 이건 말투 문제가 아니라, "유입"이라는 단어가 곧바로 "어디선가 나왔다 → 그 어디가
어디냐"는 미관측 질문을 부르기 때문이다.

## 2. 그리지 않기로 한 것 — 세 가지와 그 이유

### 2.1 섹터 → 섹터 산키/화살표 (거부)

같은 날 A 가 −1,000억, B 가 +1,000억이어도 **같은 돈이라는 증거가 없다.** 다른 주체일 수도,
신규 자금일 수도, 현금화일 수도 있다. 화살표는 미관측을 관측처럼 그린다.

그리고 실측이 이 그림의 **전제 자체**를 부정한다(§3.3): 섹터쌍 일별 흐름의 상관은 **평균이
양수**이고, 반대 부호로 움직인 쌍의 비율은 널(50%)보다 **낮다**. 즉 이 데이터에서 섹터들은
서로 반대가 아니라 **같이** 움직인다. "회전(rotation)"을 전제한 산키는 없는 현상을 그리는 셈이다.

### 2.2 주체 → 주체 전이 행렬 (거부 — 같은 실패의 다른 얼굴)

이건 반사적으로 "이건 되겠지" 싶은 자리라 명시한다. **안 된다.**

한 섹터·하루에 4주체의 순매수가 (+100, −60, −30, −10)로 관측돼도, 이는 **주변합 4개**일 뿐이다.
쌍별 이전량은 C(4,2) = **6개 미지수**이고, 주변합이 주는 방정식은 4개인데 합이 0이라
**독립인 것은 3개**다. 해공간의 차원이 6 − 3 = **3**이다 — 무한히 많은 쌍별 흐름이 같은
주변합을 만든다. 섹터→섹터를 거부한 것과 **정확히 같은 종류의 미식별**이다.

> 따라서 그리는 것은 **이분 그래프(주체 ↔ 섹터)** 이지 **주체 ↔ 주체** 가 아니다.
> 이분 그래프의 간선은 하나하나가 직접 측정된 수다.

### 2.3 잔차를 0 으로 밀어 넣기 (거부)

4주체 합은 정확히 0 이 아니다(§3.1). KRX 의 주체 분류에는 우리가 안 싣는 항목
(기타외국인 등)이 있고, 금액은 종가 환산 근사다. 예쁘게 보이려고 잔차를 4주체에 안분하면
**측정되지 않은 주체가 측정된 주체의 옷을 입는다.** 잔차는 **별도 열로 그대로 보여준다** —
`잔여 = −Σ(4주체)`. 이렇게 두면 잔차는 오차가 아니라 **미분류 주체의 순매수 추정치**라는
읽을 수 있는 값이 된다.

## 3. 실측 — 설계 판단을 만든 숫자

전부 `payload.json` 260 거래일 실측. 재현: `python scripts/ledger_numbers.py`.

### 3.1 회계 항등식은 어느 자로 재느냐에 따라 0.008% ~ 0.33% 다

**잔차의 크기는 분모를 정해야만 말할 수 있다.** 같은 −7,284억이 분모에 따라
자릿수 두 개만큼 달라 보인다.

| 분모 | 값 |
|---|---|
| 기간 총 **거래대금** 9,554조 | **0.0076%** ← 검증기(`verify_report`)가 쓰는 자 |
| 기간 총 **gross 순매수** 1,812.7조 | **0.0402%** |
| 일별 전시장 잔차 ÷ 그날 gross 순매수 | 중앙값 **0.099%**, p90 0.226%, 최대 1.515% |
| **(시장,섹터,일) 셀 단위** 잔차 ÷ gross | **0.330%** |

> 처음엔 "지시문의 0.008% 가 재현되지 않는다"고 적었다. **틀린 말이었다** —
> 검증기는 거래대금으로, 나는 gross 순매수로 나눴을 뿐이고 둘 다 맞다. 팀리드가
> 양쪽을 다 계산해 확인했다.
>
> 이 화면이 쓰는 자는 **셀 단위(0.33%)** 다. 잔여 열이 앉는 자리가 (시장, 섹터, 날짜)
> 칸이므로, 그 칸에서 잔차가 얼마나 큰지가 사용자가 실제로 마주하는 크기다.
> 시장 전체로 뭉갠 0.008% 는 "닫힌다" 는 안심을 주지만 **화면의 한 칸에서 잔여가
> 눈에 보일 만큼 크다는 사실을 지운다** — 그래서 잔여를 별도 열로 남긴다(§2.3).

### 3.2 주체별 기간 순매수 (260일, 2시장 합)

| 주체 | 순매수 |
|---|---|
| 개인 | **+75.5조** |
| 외국인 | **−154.4조** |
| 기관 | **+59.2조** |
| 기타법인 | **+19.0조** |
| 잔여(미분류) | +0.7조 |

### 3.3 섹터는 서로 **반대가 아니라 같이** 움직인다 — 널 대조

섹터 일별 흐름을 섹터 시총으로 정규화한 뒤 쌍별 상관. 널은 각 계열을 독립적으로 순환이동
(circular shift)한 것 ×20 회.

| 주체 | 원계열 상관 평균 (음수쌍 비율) | 시장요인 β 제거 후 (음수쌍) | 널의 음수쌍 |
|---|---|---|---|
| 개인 | **+0.105** (0.17) | +0.067 (0.25) | 0.50 |
| 외국인 | **+0.076** (0.24) | +0.049 (0.30) | 0.50 |
| 기관 | **+0.101** (0.23) | +0.046 (0.34) | 0.50 |
| 기타법인 | +0.011 (0.47) | −0.001 (0.51) | 0.51 |

**읽는 법.** 순수 노이즈라면 음수쌍이 50% 다. 실제로는 17~34% 다. 섹터 자금흐름은 공통
요인(위험선호)이 지배하고, **로테이션은 우연보다 드물다.** 이 한 줄이 §2.1 의 거부를 만든
직접 근거다.

⚠️ β 제거 후 가장 음의 상관을 보인 쌍은 전부 `전기/전자 ↔ 나머지`였다(외국인 기준
−0.51 ~ −0.38). 전기/전자가 시총의 대부분이라 **구성적 인공물**(compositional artifact)과
구분되지 않는다. 그래서 화면은 β 제거 계열이 아니라 **원계열**을 기본으로 보여주고, 제거는
토글로 두되 이 경고를 함께 띄운다.

## 4. 무엇을 그리나 — 네 화면

터미널 우선(§5). 모든 화면 하단에 한계 배너가 상주한다.

### 4.1 원장 (LEDGER) — 주체 × 섹터 이분 그래프의 **인접행렬**

행 = 섹터, 열 = 4주체 + 잔여. 각 칸은 부호 막대(반칸 해상도 `█`·`▌`·`▐`) + 숫자.
행 끝에 `최대1일%`(§3.4).

**노드-링크 스파게티로 안 그리는 이유:** 4×27 = 108 간선을 선으로 그리면 교차 때문에
읽을 수 없고, 선의 굵기는 눈으로 비교가 안 된다. 이분 그래프의 정보는 **인접행렬과 동치**이며
행렬은 정렬·비교·정확한 수치를 동시에 준다. 잃는 것은 "그래프처럼 보이는 것"뿐이다.

### 4.2 전개 (TIMELINE) — 섹터별 누적 순매수 스파크라인

선택 주체의 섹터별 **누적** 순매수를 `▁▂▃▄▅▆▇█` 스파크라인으로. 회전을 보여주되 화살표는
없다. 순위 교차가 눈에 보이면 그게 전부고, 그 이상은 주장하지 않는다.

### 4.3 동시성 (CO-MOVE) — 27×27 상관 히트맵 + 널

선택 주체의 섹터쌍 상관을 256색 발산 팔레트로. **헤더에 관측 음수쌍 비율과 널의 음수쌍
비율을 나란히 찍는다** — 화면이 스스로 "이 무늬가 우연보다 두드러지나"를 답한다.
칸 하나하나에 "동시에 같은/반대 방향으로 갔다"만 적고 "옮겨갔다"는 절대 안 적는다.

### 4.4 한계 (LIMITS) — 전용 화면

각주가 아니라 `?` 한 번으로 뜨는 본문. §1~§3 의 요지와 §6 의 남은 한계를 싣는다.
그리고 모든 화면 최하단에 한 줄이 상주한다:

```
관측: 주체×섹터 순매수. 미관측: 섹터→섹터 이동 · 주체→주체 이전(주변합만 있음).
```

## 5. 왜 터미널인가 — 그리고 터미널이 못 하는 것

사용자는 SSH 로 접속한다. 이 저장소가 `kq-flow` TUI 를 만든 이유가 정확히 그것이다
(3.4MB HTML 이 안 열렸다). 그래서 터미널로 먼저 진지하게 검토했고, **결과적으로 HTML 이
필요한 자리가 남지 않았다** — 아래 표의 마지막 줄이 그 판단이다.

터미널로 충분히 되는 것 — 애초에 문제가 안 됐다:

| 필요 | 터미널 수단 |
|---|---|
| 부호 막대 | 반칸 블록 `█ ▌ ▐` → 폭 14칸에 28단계 |
| 스파크라인 | 8단계 블록 `▁…█` |
| 27×27 히트맵 | 셀당 2칸(부호+세기) → 54칸 + 라벨 13칸 = 68칸, 80열에 들어간다 |
| 발산 색상 | 256색 (기존 TUI 는 8색만 씀 — 여기서 확장, 8색 폴백 유지) |

터미널로 **안 되는 것**과 그 대응:

| 안 되는 것 | 왜 | 대응 |
|---|---|---|
| 셀 단위 툴팁 / 마우스 호버 | curses 마우스는 있으나 SSH·terminfo 편차가 크다 | 커서 이동 시 **상태줄**에 그 칸의 전체 수치를 찍는다(호버의 등가물) |
| 260칸 시계열의 픽셀 해상도 | 한 행 = 최대 ~200칸 | 스파크라인은 **요약**임을 명시하고, 정확한 값은 구간 프리셋 숫자로 준다 |
| 임의 확대/축소 | — | 창(5·20·60·120·260) 프리셋 |
| 인쇄·공유 가능한 산출물 | — | `kq-ledger --dump` — 네 화면 전부를 **색 없는 평문**으로 찍는다. 파이프·리다이렉트로 SSH 밖으로 나간다. HTML 은 **안 만들었다**: 부호를 색이 아니라 글자(`+█`/`-█`)에 박아 뒀으므로 평문으로도 정보가 온전하고, 3.4MB HTML 이 안 열려서 이 TUI 가 생긴 경위를 되풀이할 이유가 없다 |

노드-링크 스파게티는 "터미널이 못 하는 것" 목록에 **없다** — §4.1 대로 어차피 안 그린다.

## 6. 남은 한계 (화면에 적힌다)

1. **금액은 종가 환산 근사.** DB 는 순매매 **수량**만 준다. 참값은 VWAP 가중.
   방향과 상대 크기용이며 원 단위 정확도를 주장하지 않는다.
2. **잔여 열은 미분류 주체 + 결측 + 환산오차의 혼합.** 순수한 "기타외국인"이 아니다.
3. **주체는 4분류뿐.** 기관 세부 6종(`detail`)은 있으나 개인/외국인은 쪼개지지 않는다.
   "외국인"은 롱온리 자금과 헤지 북이 한 칸에 들어 있다.
4. **섹터는 KRX 업종 분류.** 종목 수가 3개인 섹터(거래소/부동산)가 27개 중에 있다 —
   `종목수` 열로 표시하고 얇은 섹터는 흐리게 그린다(기존 TUI 규약 계승).
5. **생존편향.** 이 페이로드는 `require_delisted=False` 로 만들어졌고 키움 수급은 폐지
   종목에 빈 응답을 준다(MEMORY: kr-quant data gaps). 폐지된 종목의 마지막 자금흐름이
   빠져 있다 — 섹터 총량이 과소 측정되는 방향이며, 특히 코스닥에서 크다.
6. **상관은 인과가 아니고, 여기서는 동시성조차 널을 못 이긴다**(§3.3).

기존 `kq-flow` 와 나란히 둔다. `flow_view.cell_width`(East Asian Width 표준)를 **재사용**하고
폭 계산을 다시 구현하지 않는다.

### 7.2 주입해 보고 나서야 안 것 — 검사가 세 번 헛돌고 있었다

전부 "통과하고 있었지만 아무것도 안 지키던" 검사다. 주입 없이는 하나도 못 봤다.

1. **총 폭만 봤다.** 줄 전체를 `pad(line, width)` 로 감싸므로 열이 밀려도 총 폭은 늘
   맞는다 — 이 저장소가 두 번 겪은 그 실수를 검사가 통과시키고 있었다. **열 경계 칸이
   공백인지** 보는 검사로 바꿔서 잡았다.
2. **정의를 보고 화면을 안 봤다.** 잔여 열 검사가 `ledger_cols()` 만 봤는데, 렌더는 그
   목록을 `_fit` 으로 한 번 더 줄인다. 폭 60 에서 잔여가 **조용히 사라졌는데 검사는
   초록**이었다. 검사는 정의가 아니라 사용자가 보는 것을 봐야 한다.
3. **폭을 표본으로 골랐다.** 다섯 개를 골라 봤더니 전부 열 경계에 딱 떨어지는 폭이라,
   `_fit` 을 통째로 지워도 초록이었다. 잘림은 경계에 **걸치는** 폭에서만 보인다 —
   표본이 아니라 전수를 훑어야 한다.

> 그리고 `_fit` 자체가 한동안 **장식**이었다. `ledger_cols(width)` 가 `width >= 96` 같은
> 문턱으로 이미 딱 맞게 걸러 줘서, `_fit` 은 아무 일도 안 하고 있었다. 지워도 아무
> 검사가 안 깨지는 가드는 가드가 아니다. 문턱을 없애 `_fit` 을 **유일한 기제**로 만들고
> 나서야 그 제거가 검사에 걸리기 시작했다(GUARDRAILS §0 — 기제가 하나여야 산다).

### 7.3 `kq-flow` 와 같이 고친 것 (79e14df 이후 리베이스)

`kq-ledger` 는 `kq-flow` 와 같은 curses 골격 위에 있어서 **같은 지뢰를 그대로 밟는다.**
79e14df 가 flow 에서 고친 것 중 셋이 원장에도 같은 모양으로 있었고, 한쪽만 고치면 다른
쪽이 조용히 남으므로 여기서 같이 고쳤다. 스모크 테스트도 flow 의 `_run_tui`/`_drain`
헬퍼를 **일반화해서**(`app=` 인자) 재사용한다 — 헬퍼를 복사하면 둘이 갈라진다.

| flow 가 고친 것 | 원장에도 있었나 | 여기서 |
|---|---|---|
| `getch()==-1` → 100% CPU 좀비 | **있었다** | 같은 자리에 같은 분기 |
| ESC 가 종료 → 느린 SSH 에서 ↓ 로 앱이 끝남 | **있었다** | `q` 만 종료 |
| 줄을 통째로 잘라 숫자가 자릿수 중간에서 끊김 | **있었다** | `_fit` + 최소폭 가드 |
| 얇은 섹터 경고를 색에만 실음 | **있었다** | `~` 글리프 열 |
| `load()` 가 깨진 리포트에 생 트레이스백 | **있었다** | 스키마 검사 |
| 시장 순서가 해시 순서 | **있었다** | `MARKET_ORDER` 재사용 |

한 가지는 일부러 **안** 공유했다. `_fit` 은 `flow_view._fit` 을 베껴 왔다 — 지금 그쪽
열 표현이 튜플에서 객체로 바뀌는 중이라 사인이 흔들린다. 움직이는 사설 API 에 붙는
것보다 6줄을 갖는 편이 싸다. **그쪽이 정착하면 하나로 올릴 것**(후속 과제).
